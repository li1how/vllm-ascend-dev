# 工作区维护

## 工作方式

1. 先读取根 README、AGENTS 和 Git 状态，确认任务范围与已有改动。区分共享
   文件、私有生成配置、独立仓库和产物，按任务范围读取实际内容。
2. 查找修改对象的入口、调用者和生成关系，确定必要的联动改动。存在实质选择
   时说明取舍；已有明确方案时直接执行，不逐文件重复确认。
3. 保留无关修改与本机配置，复用现有公共函数和 Skill。修改后检查引用、行为
   和说明是否一致，具体检查项按下方参考文档选取。
4. 按用户最新授权执行检查，分别说明静态校验与实机验证结果；推迟的项目记录
   为待验证。Git 操作遵循对应仓库规则与已有授权，不额外提交、推送或发布。

## 按需读取

- 涉及文件增删、路径、配置或共享入口：读取 [维护检查清单](references/maintenance-checklist.md)，
  核对受影响的条目。
- 新增或修改 Bash 脚本、Shell 模板或公共函数：读取 [Shell 编写约定](references/shell-conventions.md)，
  保持参数、帮助、日志与错误处理一致。

## 文档与交付

README 面向开发者和 Agent，写工作区概览与常用入口；AGENTS 写 Agent 的
操作约束；Skill 写任务流程，较长的专项指引放入 references，避免多处复制。

交付说明改动及其原因、兼容性影响、已执行的检查和待验证项。仅在有助于审阅
时列出文件或联动表，不套用固定长报告；安装成功和容器 running 不代表 NPU 测试通过。
