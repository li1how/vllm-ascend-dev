# Shell 编写约定

常规结构参考 [profile-analyse.sh](../../../../scripts/profile-analyse.sh) 的文件头、
默认配置和参数解析部分；公共函数按需查阅 [common.sh](../../../../scripts/lib/common.sh)。
维护已有脚本时，优先阅读本次涉及的函数和调用方。

## 结构与环境

- 文件头保留 Bash shebang、简短中文用途和用法示例。示例使用可直接执行的命令，
  长短选项在帮助中并列说明，不把 `-b | --with-benchmark` 当作可执行示例。
- 公共脚本通过 `BASH_SOURCE[0]` 定位并加载 `common.sh`，调用 `ws_enter_workspace`；
  从其他目录调用也应得到正确工作区。服务模板和私有服务脚本可保持独立定位。
- 按“定位目录、默认配置、参数解析、环境检查、主逻辑”组织段落。`.env` 按需加载，
  `-h` 应在安装、网络访问和运行环境激活等操作前返回。
- 依赖和路径处理优先复用 `ws_require_commands`、`ws_require_python_module`、
  `ws_resolve_path`。需要 Python 时按根 README 的策略调用 `ws_select_python_env`，
  后续统一使用选出的 `PYTHON_BIN`，安装依赖使用 `"$PYTHON_BIN" -m pip`。

## 参数与帮助

- 面向命令行的辅助脚本提供 `-h` / `--help` 和 `print_help`；仅供 source 的库、
  通过命令数组配置的服务模板不强加参数接口。
- 常用选项沿用长短别名，例如 `-b` / `--with-benchmark`，保留已有仅长选项接口。
  帮助采用中文“用法”“选项”“示例”，写明默认值、必填项和关键组合限制。
- 带值选项先用 `ws_require_value` 等方式校验，再取 `$2` 并 `shift 2`；布尔选项
  `shift`。未知参数明确报错并返回非零，不能静默忽略。
- 支持透传参数的脚本用 `--` 分隔，并以数组保存剩余参数；同步更新文件头、
  帮助和实际调用方，不改变已有参数含义。

## 日志

公共脚本使用现有函数；独立模板沿用相同前缀，不再复制一套日志库。

| 用途 | 公共函数 | 输出标识 |
|---|---|---|
| 致命错误 | `ws_log_error` | `[ERROR]`，stderr |
| 警告 | `ws_log_warn` | `[WARN]` |
| 普通信息 | `ws_log_info` | `[INFO]` |
| 成功 | `ws_log_ok` | `[OK]` |
| 已满足条件而跳过 | `ws_log_skip` | `  [SKIP]` |
| 阶段进度 | `ws_log_step` | `>>>` |

克隆步骤可沿用 `  [CLONE]`。错误日志本身不终止脚本，需要显式返回或退出；
失败保留可定位的日志。凭据、完整代理 URL 和敏感命令参数不展开到日志。

## Bash 与退出码

- 使用 `[[ ]]`、`$(...)`、`${VAR:-default}`、`$((...))` 和函数内 `local`；
  路径与变量展开加引号，命令参数使用数组和 `"${args[@]}"`，避免拼接后 `eval`。
- 保持当前 `set -e` 或 `set -euo pipefail` 策略；新增严格选项前检查可选变量、
  conda 激活与管道行为，不机械修改所有脚本。
- 预期失败需要后续处理时，用 `if command; then ... else ... fi` 捕获结果。
  不在 `set -e` 下先运行可能失败的命令，再依赖后面的 `$?` 分支补救。
- 日志包装和管道需保留真正任务的退出码；使用 `script` 时注意 `-e`，使用 `tee`
  时检查管道退出状态。服务清理只作用于本任务创建的进程。
- 重复运行复用已满足的条件；生成配置、缓存处理和日志策略遵循相应脚本现有行为。
