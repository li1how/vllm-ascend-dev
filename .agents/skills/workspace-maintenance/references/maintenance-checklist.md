# 维护检查清单

按改动范围选择条目。小改动检查直接引用；目录重组或全工作区审查再扩大范围。

## 查找影响范围

1. 用 `git ls-files`、`git status --short` 确认版本控制范围和已有修改；用
   `rg --files --hidden` 补充相关目录中的入口，按需查看被忽略的私有配置。
   独立源码仓库、缓存和产物不纳入普通工作区文件扫描。
2. 读取修改对象，查出它使用的路径、参数和模板；再用 `rg -n` 反向搜索调用者。
   重命名同时查旧名称和旧路径，覆盖脚本、配置、文档及 Skill 元数据。
3. 只在引用较多时整理“修改对象 → 调用者”的简表，作为实施和收尾检查依据。

## 联动检查

| 修改对象 | 核对内容 |
|---|---|
| 目录或文件路径 | README 目录说明、`.code-workspace` 的 folders、脚本和文档引用；仅在实际存在时检查其他项目配置 |
| 新增或删除文件 | `.gitignore` 等实际使用的忽略规则；共享文件能入仓库，私有配置与产物不会误入 |
| 模板与 bootstrap | 模板到生成文件的路径、参数和权限；只生成缺失配置，保留已有私有配置及独立 checkout |
| Dev Container | A3/A5 保持必要的硬件差异；自动检测失败默认 A3；共享 `.devcontainer/.env`、post-create 入口和挂载路径一致 |
| 公共脚本或函数 | 参数及默认行为、工作目录、退出码、Python 环境选择；同步检查调用脚本、模板、Skill 与脚本速查 |
| IDE 配置 | 多根工作区名称、调试 cwd、解释器路径及相关任务；定向修改私有配置，不用模板整体覆盖 |
| Skill 或 Agent 配置 | 下方共享入口规则；名称、目录、描述、UI 提示词、资源链接和脚本内部调用路径一致 |
| 同步与任务执行 | 就地和远端入口均能找到公共脚本；分仓库 SHA、dirty 状态、checkout 占用、容器身份、进程归属与结果路径保持一致 |

## 共享入口

- 通用说明保留在根 README 和 AGENTS；`.claude/CLAUDE.md` 导入二者，避免
  复制另一套规则。文档职责按主 Skill 的约定区分。
- 共享 Skill 只维护 `.agents/skills/`；检查 `.claude/skills` 仍指向
  `../.agents/skills` 且能访问同一份内容。
- `.claude/`、已有 `.codex/` 及插件配置只承载对应工具的专属设置，按实际存在
  的入口检查，不为了清单补造配置。

## 收尾

- 按当前授权检查 diff、断链和旧引用；路径或入口变化时核对默认目录、导入和帮助。
- Shell 语法、lint、Skill 格式或现有测试按修改类型选择，遵守用户指定的验证范围。
  文档调整不启动安装、服务、模型测试或远端扫描。
- 检查本轮文件范围，保留无关改动和已有暂存状态；可执行脚本保留相应权限。
- 汇报实际检查结果和未验证项，发现影响交付的问题先修复；需要用户介入时说明具体阻塞。
